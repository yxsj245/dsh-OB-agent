# 0.3.0 升级说明：全局子代理模型

> 适配 DSH 0.2.1-rc.2。升级不需要迁移设置：缺省（未写入 `subagentModel`）等价于继承主会话，
> 与 0.2.0 行为一致。

## 1. 新增功能

设置页「全局」卡片新增**全局子代理模型**：

- 从 DSH 已配置的模型清单（`remote.session.modelCatalog()`）里选 provider / model，
  可选思考档位；清单与条目级模型下拉同源，用户在 DSH 设置里增删模型后会同步变化。
- 选择「继承主会话模型」= 不设置（清除固定路由），子代理跟随会话当前模型。
- 模型清单读取失败时，设置页降级为手填 provider / model，不会让整页不可用。

## 2. 优先级

固定为「条目钉死 > 全局设置 > 继承主会话」：

1. 条目里单独设置了模型：使用条目路由（固定角色可复现，不受全局切换影响）；
2. 条目未设置模型、存在全局设置：使用全局路由（`agentOptions` 传给
   `@deepseek-ai/dsh-tool-subagent`）；
3. 都没有：继承主会话（旧行为）。

设置页条目卡片的「继承」选项会显示它实际跟随的全局路由；系统提示与 `agent_list`
同样会显示每条子代理的实际路由（带「全局默认」标记）。

## 3. 边界

- 只影响本插件装配的子代理条目（`spawn` / `fork`）。DSH 原生工具条目的模型仍由 DSH
  自己的设置决定，本插件不代为改写。
- 全局设置属于用户配置：`agent_create` / `agent_update` 只读写条目级模型，不能修改它。
- 插件不校验路由是否真实存在；与条目级模型一样，由 DSH 在启动子代理时预检。
  不可用的路由表现为子代理启动失败或回退策略由宿主决定。
- 已有子代理沿用创建时的路由记录；改全局设置只影响之后新建的子代理。
- 备份会话不涉及此字段（它保存在 profile 的插件设置里，随 profile 配置一起备份）。

## 4. 验收

重启/热加载插件后刷新 GUI：

1. 设置 → 子代理 → 全局：出现「全局子代理模型」下拉，模型清单与 DSH「模型」设置一致；
2. 选一个模型 → 保存 → 勾选通用子代理并打开总开关 → 系统提示（或 `list_agents`）
   里该条目显示「模型：provider/model（全局默认）」；
3. 把条目自己钉死另一个模型：保存后条目显示自己的路由，全局设置不再覆盖它；
4. 把全局模型改回「继承主会话模型」：条目重新显示「继承 DSH 主会话」。
